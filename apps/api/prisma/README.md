# apps/api: Prisma schema

## Layout

```
prisma/
  schema.prisma          # datasource + generator config
  seed.ts                # seed placeholder
  migrations/            # migration history (Prisma Migrate)
  models/
    user.prisma            # includes the Stripe billing columns
    note.prisma            # the example table, owned by a user
    clerk-webhook.prisma   # ClerkWebhookEvent (webhook dedup table)
    stripe-webhook.prisma  # StripeWebhookEvent (webhook dedup table)
```

## Conventions

- Every table lives in the PostgreSQL `app` schema (`@@schema("app")`).
- Columns are snake_case (`@map`), tables are plural snake_case (`@@map`).
- Ids are generated by the database: `app.nanoid('<prefix>_')`, a function the
  init migration creates. Prefixes: `usr_` user, `note_` note, `evt_` webhook
  event.
- Business rows are soft-deleted through `deleted_at`; every read filters them out.
- New product tables get a `user_id` and are scoped by it in the query itself.

## Migrations

```bash
pnpm --filter @app/api db:migrate          # create + apply in development
pnpm --filter @app/api db:migrate:deploy   # apply pending migrations
pnpm --filter @app/api db:migrate:prod     # the same, retried while Postgres wakes
```

## Generated client

The Prisma client is emitted to `apps/api/generated/prisma/` (git-ignored).
From within the app, import it by relative path:

```ts
import { PrismaClient } from '../generated/prisma';
```

Run `pnpm --filter @app/api db:generate` to regenerate it
(`pnpm build` does this too).
